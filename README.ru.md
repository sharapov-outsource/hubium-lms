<h1 align="center">Hubium LMS</h1>

<p align="center">
  Открытая система дистанционного обучения, современная альтернатива Moodle.<br>
  <a href="README.md">English</a> · <b>Русский</b>
</p>

Hubium LMS умеет то, ради чего школы, вузы и компании ставят Moodle:

- курсы, роли и права;
- задания, тесты и журнал оценок;
- форумы, видео и вебинары;
- SCORM, H5P, LTI и импорт курсов из Moodle.

Сверх этого в системе есть AI-помощник, сообщения в реальном времени и спокойный интерфейс, которым удобно пользоваться с телефона. Вся система поднимается одной командой `docker compose up`. Код написан на TypeScript и распространяется под лицензией AGPL-3.0.

## Главное

- **Права как в Moodle.**
  - Контексты: сайт → категория → курс → элемент.
  - Роли хранятся в базе, права типизированы в коде.
  - Можно посмотреть курс глазами другой роли.
  - Отдельная страница объясняет, почему человеку что-то можно или нельзя.
- **Каждый элемент курса — модуль.** Страница, задание, тест, форум, видео, SCORM, H5P и LTI реализуют один контракт. В нём описаны настройки, просмотр, оценивание, выполнение, календарь, резервная копия, импорт из Moodle, приватность и текст для AI. Сторонний модуль — это пакет плюс одна строка в конфигурации.
- **Одна операция — три транспорта.** Бизнес-логика живёт в операциях `packages/core` вместе с проверкой прав. Интерфейс, REST API и фоновый воркер вызывают один и тот же код.
- **AI с заботой о данных.**
  - Работает с Claude или любым OpenAI-совместимым сервером: Ollama, vLLM, YandexGPT.
  - Выключен, пока администратор не выберет провайдера.
  - Просит согласия у пользователей и соблюдает квоты.
  - Перед проверкой обезличивает работы студентов.
- **Стандарты и переезд:** SCORM 1.2/2004, H5P, LTI 1.3 Advantage, импорт `.mbz` из Moodle 4.1–5.x, вопросы в GIFT и Moodle XML.
- **Локальные узлы для плохой связи.** Сервер в сети филиала обслуживает людей с реплики облака и продолжает работать, когда связи с облаком нет: тесты, задания, форумы и все остальные элементы. Сделанное без связи уходит в облако, когда связь возвращается. Облако проверяет это заново, а непринятое становится конфликтом, который может принять преподаватель. К одному облаку подключается сколько угодно узлов, каждый ставится одной командой с кодом из облака. Подробнее — в разделе [Локальные узлы](#локальные-узлы) ниже.
- **Готово к эксплуатации:**
  - один скрипт ставит релиз в Docker или в систему с systemd, с HTTPS (Caddy);
  - отдельные воркеры для задач и для видео;
  - JSON-логи, проверки здоровья и метрики Prometheus;
  - CI на каждом коммите ставит оба вида релиза так же, как пользователи, и проверяет их сквозными сценариями;
  - сценарии обрывов связи с локальными узлами идут на каждом коммите, а весь набор сквозных сценариев через узел и стенд облака с филиалами, установленными как в жизни, — в длинных проверках, которые запускаются вручную.

## Возможности

### Курсы и обучение

- Дерево категорий.
- Форматы курса: «темы», «недели», «одна страница». Обложки, каталог с полнотекстовым поиском (формы слов, начала слов, опечатки), страница курса.
- Разделы и элементы:
  - порядок меняется перетаскиванием или с клавиатуры («Переместить в…»);
  - подразделы внутри раздела, среди его элементов, сворачиваются;
  - видимость: показан, скрыт, доступен только по ссылке;
  - удалённое попадает в корзину и восстанавливается.
- Условия доступа к элементам и разделам: дата, выполнение, оценка, группа, группировка, поле профиля (включая свои поля).
- Выполнение: вручную или автоматически, с отметкой преподавателя. Есть матрица выполнения и прогресс по курсу.
- Запись на курс:
  - ручная;
  - самостоятельная по ключу курса или ключам групп, с окном записи и сроком участия;
  - синхронизация с глобальными группами, гостевой доступ;
  - истечение сроков обрабатывается по расписанию.
- Группы и группировки курса (элемент можно ограничить группировкой), глобальные группы, список участников с фильтрами и массовыми действиями.
- Дашборд: «продолжить», «к выполнению» и ближайшие сроки. Лента курса в духе Google Classroom.
- Отчёты курса: участие и журнал событий (с отбором по локальному узлу).
- Наставники и родители (по желанию): администратор связывает их с учениками, и они видят курсы, прогресс, оценки и сроки учеников, но не действуют за них.

### Элементы курса

| Модуль | Что умеет |
|---|---|
| Страница, ссылка, файл, метка | Форматированный текст с таблицами, картинками и формулами (KaTeX). Ссылки открываются в странице, в новой вкладке или встраиваются. Ресурсы из нескольких файлов. Встраивание YouTube, RuTube и VK Video |
| Книга | Главы и подглавы с оглавлением и нумерацией, скрытые главы, переход к предыдущей и следующей, вся книга на одной странице для печати |
| Опрос | Один или несколько вариантов, лимиты мест, смена ответа, даты. Результаты после ответа, после закрытия или всегда, с именами или без, раздельные группы, выгрузка ответов в CSV |
| Анкета | Пояснения, короткие и развёрнутые ответы, выбор из вариантов, числа, разрывы страниц, обязательные вопросы. Анонимно или с именами, даты, сводка с диаграммами (по желанию и для студентов), ответы в CSV и XLSX |
| Глоссарий | Статьи преподавателей и студентов с другими формами понятия и категориями, одобрение статей студентов, поиск и указатель по буквам, рейтинги статей в журнал, выполнение по числу статей. Понятия в текстах курса становятся ссылками на свои статьи |
| Лекция | Страницы с материалом и кнопками и страницы с вопросами (множественный выбор, верно/неверно, короткий ответ, числовой, соответствие, эссе), связанные переходами в зависимости от ответов; ветки и кластеры, попытки на вопрос, свои баллы, повторное прохождение (лучшая или средняя оценка), ограничение времени, пароль, даты, меню и индикатор прохождения. Проверка эссе и отчёт по попыткам, оценка в журнал |
| Вики | Совместная или индивидуальная, у каждой группы своя в групповом режиме. Ссылки между страницами [[Заголовок]] (недостающую страницу можно написать прямо по ссылке), список всех страниц и страниц-сирот, история версий со сравнением и восстановлением, блокировка страницы на время правки, выполнение по числу правок |
| База данных | Поля, которые задаёт преподаватель (текст, многострочный текст, число, дата, список, переключатели, флажки, ссылка, файл, изображение), шаблоны с [[поле]] для списка и страницы записи, поиск и сортировка, одобрение, ограничение числа записей, записи до просмотра чужих, групповой режим, рейтинги в журнал, выгрузка в CSV и XLSX, импорт из CSV |
| Семинар | Взаимное оценивание по этапам, которые переключает преподаватель или дата: форма оценивания (накопительная, комментарии, число ошибок, рубрика), сдача работ, распределение рецензентов вручную или случайно (без участников той же группы, с самооценкой), оценка за работу по рецензиям с весами и оценка за оценивание сравнением с лучшей оценкой, переопределение преподавателем, публикация работ; обе оценки — в журнал |
| Задание | Текст и файлы, лимит слов, даты открытия, срока и жёсткого срока. Сроки для студентов и групп, командные сдачи, заявление об авторстве, штраф за каждый день опоздания с пределом, повторные попытки, оценка в баллах или по шкале. Рубрики и листы оценивания, этапы проверки с назначением проверяющих, слепая проверка, отзыв с файлами. Все работы можно скачать одним zip-архивом |
| Тест | Банк вопросов на 14 типов, среди них упорядочивание, выбор пропущенных слов, перетаскивание в текст, вложенные ответы (Cloze) и вычисляемые вопросы с наборами данных; случайные вопросы из категории, перемешивание. Лимит времени проверяется на сервере, и тест закрывается, даже если браузер закрыт. Автосохранение. Отложенный, немедленный или интерактивный отзыв: подсказки между попытками и штраф за каждую неверную. Пароль, сетевые адреса или только сети выбранных локальных узлов, паузы между попытками, страницы по порядку. Методы оценивания, настройки просмотра результатов, сроки, время и попытки для отдельных студентов и групп, ручная проверка эссе, переоценка с пробным прогоном, статистика по вопросам |
| Форум | Обычный и «вопрос-ответ». Подписки: по желанию, автоматически или принудительно. Групповые режимы, закреплённые и закрытые темы, приватные ответы, непрочитанное, выполнение по сообщениям. Рейтинги постов (от преподавателей, а если разрешено, и от студентов) и оценка за весь форум, каждая в журнале |
| Видео | Загрузка с докачкой. Перекодирование в HLS 360/720/1080p, но не выше исходника. Постер и превью при перемотке, субтитры VTT/SRT, запрет перемотки вперёд по желанию, выполнение при N% просмотра |
| Вебинар | BigBlueButton с записями и Jitsi. Расписание в календаре, роль ведущего или участника по правам, посещаемость |
| SCORM | SCORM 1.2 и 2004 с отдельного домена. Попытки, метод оценивания, отчёт и отладка CMI |
| H5P | Пакеты `.h5p` с библиотеками проигрываются с отдельного домена через h5p-standalone (содержимое создаётся в H5P или Moodle, редактора нет). Каждый результат, который содержимое сообщает по xAPI, — попытка; метод оценивания, оценка в журнал, выполнение по прохождению, сдаче или баллу, панель проигрывателя и права использования по выбору, отчёт по попыткам |
| LTI | Платформа LTI 1.3: OIDC-запуск, Deep Linking, оценки в журнал (AGS), списки участников (NRPS). Ключи RS256 с ротацией и JWKS |

### Оценивание

- Журнал оценок:
  - дерево категорий и шесть методов агрегирования: натуральный, среднее, взвешенное среднее, максимум, минимум, медиана;
  - веса элементов и категорий, отбрасывание худших, учёт только лучших и только оценённых;
  - показ в баллах, процентах или буквах, границы букв для сайта и для курса.
- Шкалы сайта и курса: по ним оцениваются ручные элементы и задания.
- Вычисляемые элементы: формула над другими элементами и категориями по ID-номеру (`=([[hw1]] + [[hw2]]) / 2`), пересчёт с каждой оценкой.
- Отчёт оценщика с правкой прямо в таблице и итогами категорий, отчёт студента, история оценок с фильтрами. Импорт из CSV, XLSX или ODS: столбцы сопоставляются с элементами, перед загрузкой видно, что изменится. Экспорт в CSV, XLSX и ODS.
- Банк вопросов:
  - типы: множественный выбор, верно/неверно, короткий ответ, числовой, на соответствие, эссе, описание;
  - теги и черновики;
  - импорт и экспорт в GIFT и Moodle XML.

### Коммуникации

- **Уведомления:** в приложении, по почте (сразу или дайджестом в удобный час по местному времени) и Web Push. Каждый тип настраивается отдельно, от писем можно отписаться в один клик.
- **Сообщения:**
  - личные, групповые и чаты групп курса в реальном времени (SSE);
  - «печатает…» и вложения;
  - блокировки и настройки приватности.
- **Объявления:** сайта и курса, с закреплением и отложенной публикацией.
- **Календарь:**
  - события сайта, курса, группы и личные, с местом проведения;
  - виды «день», «неделя», «месяц» и «список»;
  - напоминания и подписка iCal на календарь Hubium;
  - импорт файлов .ics и подписка на внешние календари по адресу: обновление раз в час, день или неделю, повторяющиеся события разворачиваются.

### AI-помощник

- **Тьютор курса:**
  - отвечает по материалам курса со ссылками на источники, используя гибридный поиск (полнотекстовый + pgvector);
  - не видит скрытых материалов и вопросов тестов;
  - недоступен во время попытки теста.
- **Генерация вопросов** по страницам и загруженным документам (PDF, DOCX, PPTX, ODT, ODP). Вопросы попадают в банк черновиками, преподаватель их проверяет.
- **Помощник проверки:**
  - читает работу вместе с вложениями: PDF, DOCX, PPTX, ODT и текстовыми файлами;
  - предлагает оценку и отзыв, а сохраняет их преподаватель.
- **Управление:**
  - включение по функциям и курсам;
  - квоты на пользователя и на курс, сводка использования;
  - уведомление о приватности с согласием.

### Перенос курсов

- Резервная копия `.hubium`, восстановление и копирование курса, импорт выбранных элементов из другого курса; сброс курса для нового потока со сдвигом всех дат.
- Импорт резервных копий Moodle `.mbz` (4.1–5.x):
  - переносятся страницы, метки, ссылки, файлы и папки, книги, задания, тесты с банком вопросов, форумы, опросы, анкеты, лекции со страницами, SCORM, H5P и BigBlueButton;
  - у глоссариев, вики, баз данных (с полями и шаблонами) и семинаров (с формой оценивания) — настройки;
  - у заданий — команды, этапы проверки, слепая проверка, рубрики и листы оценивания, сроки групп; у форумов — рейтинги и оценка за весь форум;
  - группы и группировки (без участников), шкалы и журнал: категории, ручные элементы, ID-номера, формулы и буквенные оценки;
  - остальные элементы становятся метками, чтобы ничего не потерялось незаметно;
  - по каждому импорту формируется отчёт.

### Администрирование

- Пользователи: создание и правка, свои поля профиля, блокировка, вход от имени пользователя (с возвратом), загрузка из CSV (пользователей, групп курса и глобальных групп, с предпросмотром), массовые действия с выбранными (приостановка, удаление, смена пароля, глобальная группа, запись на курс, сообщение, выгрузка в CSV, XLSX и ODS), выгрузка персональных данных, удаление с обезличиванием.
- Редактор ролей с матрицей прав, переопределения прав в категории, курсе и элементе, проверка прав.
- Категории и курсы с корзиной и своими полями курса (видны в каталоге и служат его фильтрами), глобальные группы, инструменты LTI, вебхуки, AI-провайдер, политики с обязательным принятием, объявления сайта.
- Модули элементов курса включаются и выключаются для всего сайта; выключенный модуль сохраняет элементы и оценки до повторного включения.
- Настройки:
  - общие;
  - оформление: фирменный цвет с автоматической поправкой контраста и логотип;
  - регистрация и способы входа;
  - почта с тестовой отправкой;
  - режим обслуживания: сайтом пользуются только администраторы, остальным — сообщение (также `hubium maintenance on|off`).
- Страница «Окружение» проверяет базу, воркер, очередь задач, хранилище, SMTP, домен контента, Web Push, AI и ffmpeg.
- Страница «Задачи»: задачи по расписанию с последним запуском и ручным запуском, журнал всех запусков за 30 дней с повтором неудачных.

### Интеграции

- REST API v1 с описанием OpenAPI 3.1 и интерактивным справочником на `/api/v1/docs` (отдаётся самим сайтом, работает без интернета): пользователи, курсы и поиск по каталогу, записи, группы, журнал оценок, все действия модулей с загрузкой файлов, календарь, сообщения, вебхуки. Персональные токены с правом чтения или записи.
- Вебхуки о пользователях, курсах, записях, оценках, выполнении, сданных работах и попытках тестов. Подпись HMAC-SHA256, повторы с нарастающей паузой.
- `/api/health` и метрики Prometheus на `/api/metrics`.

### Локальные узлы

- **Узел** — сервер в сети филиала или корпуса с репликой базы и копией файлов облака. Люди открывают привычный адрес (DNS сети ведёт на узел): страницы и файлы идут из сети здания, изменения — в облако.
- **Без связи** узел через две минуты начинает работать сам: тесты с лимитом времени, задания, форумы, вики, оценки, правка курсов, вход по паролю. Не работают администрирование сайта, AI, LTI и вебинары.
- **Когда связь возвращается,** узел передаёт журнал сделанного, и облако выполняет каждое действие заново по своим правилам, ровно один раз, даже если передача оборвалась. Непринятое становится конфликтом: автор получает уведомление, а преподаватель может принять работу вопреки сроку или лимиту попыток.
- **«Администрирование → Узлы»:** состояние, отставание реплики, копирование файлов, обрывы связи, конфликты, администраторы узла и отзыв одним действием. Администратор узла на странице `/node` переводит узел в автономный режим перед экзаменом и откладывает синхронизацию до конца занятия.
- **В курсах:** тест можно разрешить только в сетях выбранных узлов, а журнал событий показывает, через какой узел пришло событие.
- **Обслуживание:** узел обновляется вслед за облаком и получает от него сертификаты, метрики узлов идут в Prometheus.

### Платформа

- **Вход:**
  - по почте или логину (для учеников без почты);
  - подтверждение почты, двухфакторная аутентификация (TOTP) с резервными кодами и фразами восстановления на случай потери телефона;
  - политика паролей: длина, классы символов, запрет повторов, срок действия;
  - блокировка после неудачных попыток входа с разблокировкой по ссылке из письма;
  - уведомление о входе с нового устройства и ссылка «это был не я»;
  - вход через Google, Яндекс ID, VK ID, Keycloak и свои провайдеры OAuth 2;
  - единый вход по OpenID Connect и SAML 2.0 (Keycloak, Microsoft Entra ID, ADFS, Okta и другие) с сопоставлением полей профиля;
  - вход через LDAP (OpenLDAP, Active Directory, FreeIPA) с ночной синхронизацией;
  - управление активными сеансами.
- **Интерфейс:**
  - устанавливаемое PWA с офлайн-страницей и push-уведомлениями;
  - русский, английский, французский, немецкий и итальянский языки. Язык — это набор JSON-файлов ([docs/i18n.md](docs/i18n.md)); администратор ставит пакет из интерфейса (новый язык или новую версию встроенного, без пересборки), включает языки и задаёт язык сайта;
  - светлая и тёмная темы;
  - мобильная вёрстка с нижней навигацией.
- **Доступность:** каждый сквозной сценарий проверяется axe на серьёзные и критичные нарушения.
- **Безопасность:**
  - CSP с nonce на каждый запрос, проверка Origin;
  - защита от SSRF для исходящих запросов;
  - лимиты загрузок, недоверенный контент на отдельном домене.

  Подробности — в [docs/security.md](docs/security.md).

## Установка

Каждый релиз публикуется в трёх видах:

- Docker-образы `ghcr.io/sharapov-outsource/hubium-lms` и `hubium-lms-media` для amd64 и arm64;
- архив `hubium-<версия>-linux-x64.tar.gz` или `-linux-arm64.tar.gz` — вся система вместе с Node.js;
- скрипт `install-hubium.sh`, который ставит любой из них.

### Что нужно

- **Сервер.** Linux на x86_64 или arm64: от 2 ядер, 4 ГБ памяти и 10 ГБ диска. Перекодирование видео на время работы берёт ещё до 2 ядер и 2 ГБ.
- **Для установки в Docker** — любой дистрибутив с Docker Engine 24+ и Compose 2.20+. На Debian и Ubuntu установщик может поставить Docker сам.
- **Для установки в систему** — Debian 12/13 или Ubuntu 22.04/24.04/26.04 с systemd. На других дистрибутивах — с `--skip-packages`, если сами поставите:
  - PostgreSQL 16+ с pgvector;
  - Caddy или другой обратный прокси;
  - ffmpeg для видео.
- **Доменные имена**, указывающие на сервер:
  - сайт, например `lms.example.org`;
  - недоверенный контент SCORM и H5P, например `content.example.org`;
  - скачивание файлов, например `files.example.org` — только если Docker поднимает своё S3-хранилище.
- **Порты 80 и 443** свободны, если сертификаты получает Caddy.

### Быстрый старт

```bash
curl -fsSLO https://github.com/sharapov-outsource/hubium-lms/releases/latest/download/install-hubium.sh
sudo bash install-hubium.sh
```

Скрипт проверяет сервер, затем задаёт вопросы:

1. Установка в Docker или в систему.
2. Адрес сайта и хост для контента.
3. HTTPS: Caddy с автоматическими сертификатами или свой прокси (для nginx установщик пишет готовый сайт).
4. Какие модули элементов курса ставить: задания, тесты, форумы, видео, вебинары, SCORM, H5P, LTI. Остальные элементы есть всегда.
5. База данных: поставить PostgreSQL на сервер или подключить существующий.
   - Существующий PostgreSQL скрипт сначала проверяет.
   - Если не хватает прав или расширений, он печатает SQL для администратора БД.
6. Где хранить файлы: на сервере или в S3.
7. Почта (SMTP).
8. Первый администратор и нужны ли демо-курсы.

После сводки и подтверждения скрипт:

- генерирует секреты;
- скачивает релиз и сверяет контрольную сумму;
- при необходимости ставит PostgreSQL, Caddy и ffmpeg;
- создаёт базу;
- запускает сервисы и ждёт, пока они ответят.

В конце печатает адрес и пароль администратора.

Невыбранный модуль выключен, но не удалён. Его можно включить позже в **Администрирование → Модули** или командой `hubium modules enable <имя>`.

### Установка без вопросов

У каждого вопроса есть параметр (`bash install-hubium.sh --help`), а `--yes` берёт значения по умолчанию для остального:

```bash
sudo bash install-hubium.sh --yes --mode native --domain lms.example.org \
  --modules assign,quiz,forum --smtp-url smtp://user:pass@smtp.example.org:587 \
  --mail-from "LMS <no-reply@example.org>" --admin-email admin@example.org
```

`--dry-run` показывает шаги и ничего не меняет.

### Что где лежит

| | Docker | В системе |
|---|---|---|
| Программы | образы, `/opt/hubium/compose.yml` | `/opt/hubium/releases/<версия>`, `/opt/hubium/current`, `/usr/local/bin/hubium` |
| Настройки | `/opt/hubium/.env` | `/etc/hubium/hubium.env` |
| Данные | тома Docker `db`, `data` (и `s3`) | PostgreSQL, `/var/lib/hubium` |
| Сервисы | `docker compose --project-directory /opt/hubium ps` | `systemctl status hubium-web hubium-worker` |
| Логи | `docker compose --project-directory /opt/hubium logs -f` | `journalctl -u 'hubium-*' -f` |

Команда `hubium` проверяет и обслуживает установку. В Docker её запускают через `docker compose --project-directory /opt/hubium exec web hubium …`.

| Команда | Что делает |
|---|---|
| `hubium doctor` | проверяет настройки, базу, воркер, хранилище, почту, ffmpeg и антивирус |
| `hubium modules list\|enable\|disable` | показывает модули, включает и выключает их |
| `hubium migrate --seed minimal` | применяет миграции; Docker делает это при каждом запуске |
| `hubium secrets rotate` | перешифровывает сохранённые секреты после смены `APP_SECRET` |
| `hubium ai reindex [--course <id>] [--sync]` | перестраивает индекс поиска AI-тьютора, например после смены модели эмбеддингов |
| `hubium version` | показывает версию и коммит |
| `hubium nodes list\|add\|code\|revoke` | в облаке: локальные узлы, новый узел с кодом установки, новый код, отзыв |
| `hubium node status\|offline\|online\|postpone` | на узле (`docker compose --project-directory /opt/hubium/node exec agent hubium node …`): состояние, работа без облака, возврат к облаку, отложить синхронизацию |

### Обновление

```bash
sudo bash install-hubium.sh upgrade                    # до релиза, с которым пришёл скрипт
sudo bash install-hubium.sh upgrade --version 1.2.0
```

Обновление по шагам:

1. Резервная копия базы в `/var/backups/hubium`.
2. Загрузка нового релиза.
3. Миграции.
4. Перезапуск сервисов.

При установке в систему предыдущие релизы остаются рядом.

### Установка локального узла

В облаке (установка в Docker) один раз включите узлы. Затем добавьте узел в **Администрирование → Узлы** и выполните на сервере филиала команду с кодом, которую покажет облако:

```bash
sudo bash install-hubium.sh enable-nodes                                       # в облаке
sudo bash install-hubium.sh --node --hub https://lms.example.org --code <код>   # на сервере узла
```

Требования к серверу узла, DNS сети филиала и настройка внешней базы описаны в [docs/operations.md](docs/operations.md#локальные-узлы), работа с узлами в интерфейсе — в [руководстве администратора](docs/guide/06-admin.md#локальные-узлы).

### Без скрипта

- **Docker.** Возьмите из релиза `compose.yml`, `Caddyfile` и `env.production.example`. Последний сохраните как `.env` рядом с `compose.yml` и заполните.
  - Необязательные сервисы — профили compose: `db`, `s3`, `caddy`, `media`, `mailpit`, `clamav` (проверка загрузок на вирусы) и `ai-local` (Ollama с bge-m3 для поиска AI-тьютора).
  - Запуск: `docker compose pull && docker compose up -d --wait`.
- **Архив.** Распакуйте и следуйте `README.txt` внутри:
  1. Заполните `/etc/hubium/hubium.env` по `deploy/hubium.env.example`.
  2. Выполните `hubium doctor db` и `hubium migrate --seed minimal`.
  3. Установите юниты systemd из `deploy/systemd`.
  4. Настройте обратный прокси.
- **Из исходников.** В клоне репозитория: `docker compose -f docker/compose.yml --env-file .env up -d --build` — образы собираются, а не скачиваются.

### После установки

1. Войдите администратором и смените пароль.
2. Откройте **Администрирование → Окружение**: все проверки должны быть зелёными.
3. Задайте название сайта, оформление, регистрацию и почту. Если нужен AI, подключите провайдера.

Резервное копирование, обновление, ротация секретов, мониторинг и масштабирование описаны в [docs/operations.md](docs/operations.md).

## Разработка

Нужны:

- Node.js 22.12+ (рекомендуется 24 LTS);
- pnpm 12 (`npm install -g pnpm@12`);
- Docker;
- ffmpeg для видео.

```bash
cp .env.example .env                              # задайте APP_SECRET: openssl rand -base64 32
docker compose -f docker/compose.dev.yml up -d    # PostgreSQL, RustFS (S3), Mailpit
pnpm install
pnpm db:migrate
pnpm db:seed --profile demo
pnpm dev                                          # http://localhost:3000
```

- Администратор: `admin@hubium.local` / `Admin12345!`.
- Демо-пользователи `teacher`, `assistant`, `student1`…`student3`, `manager` и `parent` (родитель `student1`), пароль `Demo12345!`.
- Демо-курсы:
  - «Python для начинающих»: страницы, задание, тест, форум, видео и онлайн-занятие, ИИ на встроенном тестовом провайдере;
  - «История русской литературы XIX века»: элементы остальных типов (книга, глоссарий, опрос, анкета, лекция, вики, база данных, семинар, SCORM и H5P), подразделы, а также ответы, записи и оценённые эссе трёх студентов.
- На сайте есть значки (два уже выданы), сертификат, рамка компетенций с планами обучения, отчёт для менеджеров, своё поле профиля и поле курса.
- Демо-данные добавляются один раз, при первом наполнении базы. Чтобы увидеть новые демо-данные в уже наполненной базе, создайте её заново.
- Исходящая почта: http://localhost:8025 (Mailpit).

| Команда | Что делает |
|---|---|
| `pnpm dev` | приложение и воркер в режиме разработки |
| `pnpm lint` / `pnpm format` | Biome |
| `pnpm typecheck` | TypeScript во всех пакетах |
| `pnpm test` | unit и интеграционные тесты на PostgreSQL (тесты S3 — с `S3_TEST_ENDPOINT`) |
| `pnpm --filter @hubium/e2e e2e` | сценарии Playwright против запущенного приложения, с проверкой axe |
| `pnpm --filter @hubium/e2e stack` | проверка продакшен-стека в Docker (см. [CONTRIBUTING.md](CONTRIBUTING.md)) |
| `pnpm --filter @hubium/e2e nodes` | сценарии локальных узлов: облако и два узла на одной машине, связь между ними рвётся (нужны Docker и собранные web, worker и cli) |
| `pnpm depcruise` | архитектурные границы |
| `pnpm licenses:check` | лицензии зависимостей совместимы с AGPL-3.0 |

## Устройство проекта

| Путь | Что внутри |
|---|---|
| `apps/web` | Next.js 16: интерфейс, server actions, REST API, SSE, файловые роуты |

| `packages/module-sdk` | контракт, который реализуют модули элементов курса |
| `packages/ui`, `packages/editor` | дизайн-система и редактор Tiptap |
| `packages/ai`, `packages/questions`, `packages/interchange` | провайдеры LLM и извлечение текста; типы и форматы вопросов; резервные копии и импорт из Moodle |
| `packages/api`, `packages/i18n`, `packages/log` | REST API, переводы, структурные логи |
