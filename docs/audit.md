# Аудит кода: сводка

Полный аудит кода Hubium LMS и исправления по его итогам. Здесь — охват, метод, числа и что сделано. Подробный отчёт с местами в коде и сценариями хранится вне репозитория: он описывает, как воспроизвести уже исправленные уязвимости. О новых уязвимостях сообщайте так, как описано в [SECURITY.md](../SECURITY.md).

## Охват

Весь репозиторий, около 145 тысяч строк TypeScript:

- приложения `apps/web`, `apps/worker`, `apps/cli`;
- пакеты `packages/*` и 17 модулей элементов курса в `modules/*`;
- схема и миграции базы данных;
- e2e-сценарии, Docker, systemd, установщик, CI;
- документация.

Не в счёт — сознательные ограничения из [сравнения с Moodle](moodle-comparison.md) (раздел «Чего не делаем»).

## Метод

- **Ручная проверка** в восьми областях: безопасность и вход; ядро учебного процесса; значки, компетенции, отчёты, банк вопросов и AI; элементы курса (две части); веб-администрирование; страницы обучения и i18n; платформа. Каждая находка прослежена от реального входа (страница, server action, REST API, фоновая задача) до места ошибки.
- **Сведение.** Дубли из разных областей объединены, самые серьёзные находки перепроверены, часть воспроизведена на запущенном приложении.
- **Автоматические проверки:** Biome, проверка типов, архитектурные правила (dependency-cruiser), лицензии, `pnpm audit`, юнит-тесты с покрытием, e2e, поиск мёртвого кода (knip), сверка ключей i18n с кодом, сверка схемы БД с миграциями.
- **Ограничения.** Нагрузочного тестирования не было: оценки производительности сделаны по коду. Внешние интеграции (BBB, Jitsi, реальные провайдеры входа, S3, ClamAV) проверялись по коду и тестам.

## Исходное состояние

Автоматические проверки были чистыми: lint, типы, архитектурные границы, лицензии, известные уязвимости зависимостей. Проходили все 831 юнит-тест и 114 e2e-сценариев, серверный код был покрыт тестами на 84,6 % строк. Права проверялись последовательно через операции ядра, сырой SQL параметризован, недоверенный контент (SCORM, H5P) изолирован отдельным origin.

Найденные проблемы лежали в основном на стыках: ядра и библиотеки входа, модулей и журнала оценок, формы и операции, удаления, копирования и сброса курса.

Уровни:

Отдельно от этих чисел разобраны мёртвый код, пробелы в тестах и 13 предложений по рефакторингу.

### Группы рисков

- **Правила оценивания и права.** Не все проверки учитывали ввод, которого интерфейс не отправляет сам; раздельные группы и скрытые курсы учитывались не на всех путях к данным (фильтры, прямые ссылки, уведомления).
- **Видимость скрытого.** Скрытые оценки, анонимные ответы и тексты из недоступных элементов могли попасть к тем, кому они не предназначены.
- **Учёт и целостность данных.** Журнал оценок и прогресс не всегда пересчитывались после изменения настроек; при правке, сбросе и удалении часть данных терялась.
- **Перенос курсов.** Импорт из Moodle, резервное копирование и копирование курса — ошибки на типичных курсах, архивы целиком в памяти, пустые копии.
- **Устойчивость и масштаб.** Дорогие проверки ввода, списки без постраничного вывода, запросы на каждого участника.
- **Персональные данные.** Удаление пользователя оставляло часть его данных.
- **Интерфейс.** Сообщения об ошибках на английском в русском интерфейсе, пробелы доступности, пункты меню, недоступные с телефона.
- **Платформа.** Пропущенные в CI тесты, порядок миграций, установка и обновление, расхождения документации с кодом.

## Исправления

Шесть фаз по убыванию риска; каждая находка попала ровно в одну.

1. **Критичные находки и эксплуатируемые уязвимости.**
2. **Остальная безопасность и персональные данные:** вход и привязка внешних учётных записей, раздельные группы, удаление пользователя.
3. **Учёт и целостность данных:** оценки, выполнение, сертификаты и значки; удаление, копирование, сброс и импорт курсов; сообщения об ошибках на языке интерфейса.
4. **Интерфейс, i18n, доступность:** формы, загрузки больших файлов, телефоны, клавиатура и программы экранного доступа.
5. **Производительность и масштаб:** постраничный вывод, пакетные запросы, потоковая работа с архивами.
6. **Платформа, документация, мёртвый код, рефакторинг, тесты.**

Порядок работы в каждой фазе: исправление вместе с тестом, который воспроизводит сценарий находки; lint, типы, архитектурные правила, лицензии, все юнит-тесты и полный e2e; отправка в `main` только после зелёного CI предыдущей.

### Решения о поведении

Там, где исправление требовало выбрать поведение, выбрано поведение Moodle:

- итог курса для студента считается без скрытых от него элементов;
- достигнутое завершение курса не снимается;
- обсуждения форума удалённой группы сохраняются и видны тем, кто видит все группы;
- групповой режим в задании и тесте фильтрует работы, а не только хранится в настройках;
- вес элемента показывается и меняется только во взвешенном среднем;
- привязка входа через SSO и LDAP к существующей учётной записи по почте у новых провайдеров выключена, требует подтверждённой почты и не привязывает администраторов;
- аудитория отчётов «по ролям» — системные назначения ролей;
- недоделанные функции доделаны (выход из курса, удаление категории вопросов, ожидаемая дата выполнения в календаре, пометка заблокированных оценок, подкатегории для случайных вопросов), а ключи переводов без функций удалены.

### Рефакторинг

Сделаны: одна проверка логинов с правами, общие хелперы форм и формы своих полей, разделение крупных server actions, один источник статусов ошибок, ошибки как ключи сообщений, общий код модулей (поле файлов, CSV, разбор ссылок на видео, штраф за опоздание), общие функции учащихся и процента оценки, тексты UI-кита из одного источника, группы событий вебхуков, связанные со списком событий ядра.

Не сделаны три архитектурных предложения: контекст модуля, ограниченный самим модулем; пересчёт производных данных из одной точки; одна функция видимости для всех списков. Находки, которые они закрыли бы, исправлены по месту; описание контракта модулей приведено в соответствие с кодом ([modules.md](modules.md)).

### Тесты

Добавлены тесты к исправлениям, юнит-тесты воркера и хелперов server actions, проверка порядка миграций и ручных индексов, проверка ключей i18n по коду. Новые e2e-сценарии: раздельные группы (участники, форум, задание), студент в поясе западнее UTC, импорт .mbz через интерфейс, корзины элементов и курсов, доступность всех пунктов меню с телефона. e2e работают на отдельной базе (`E2E_DATABASE_URL`) и возвращают изменённые настройки сайта.

### Мёртвый код

Удалены неиспользуемые файлы, экспорты и зависимости, а также таблицы и поля схемы, которые никто не читал и не писал (миграцией).

## Сверка после исправлений

После шести фаз каждая находка заново сверена с кодом, вместе с 16 дополнительными замечаниями. Из 169 находок 150 оказались исправлены полностью, 17 — частично: исправление не покрывало один из путей к тем же данным или один из модулей. Ещё две закрыты решением о поведении. Частично исправленные доделаны, каждая с тестом, как и замечания к исправленным: оценка в сертификате без скрытых элементов, эссе прежних попыток лекции, удаление файлов модулей при откате импорта только после фиксации транзакции.

Сознательно оставлено:

- импорту курса нужен общий с веб-сервером каталог загрузок, даже при S3 ([operations.md](operations.md));
- видео, обработанное с удалением исходного файла, копия и восстановление не переносят: отчёт восстановления и само видео просят загрузить его снова;
- завершённая попытка SCORM ещё несколько минут принимает сохранения от открытого плеера, которые тот отправляет при выходе; новая загрузка плеера открывает её только для просмотра;
- длительность встроенного видео задаёт первый отчёт плеера, дальше она может только расти;
- отозванный или истёкший значок возвращается вручную, а не сам при повторном выполнении условий;
- удалённое своё поле отчёты отбрасывают при чтении, а не запрещают удалять используемое.
