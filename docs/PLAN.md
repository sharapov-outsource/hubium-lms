# Hubium — open-source LMS: современная альтернатива Moodle

## Контекст

Moodle умеет почти всё, но интерфейс у него устаревший и неудобный, а расширять его дорого. Цель — открытый движок (AGPL-3.0) с той же глубиной: курсы, роли, задания, тесты, журнал оценок, плагины, стандарты SCORM/LTI, импорт из Moodle. При этом интерфейс должен быть современным и удобным, а установка — одной командой `docker compose up`.

Проект пишется с нуля. Название — **Hubium** («Хабиум»: Hub + латинское -ium, как в gymnasium), scope пакетов `@hubium/*`. Каждая установка задаёт своё название, логотип и цвет в админке.

Подробный технический разбор (контракты, схемы, `can()`, детали LTI/SCORM/AI) — в [architecture.md](architecture.md).

## Принятые решения

| Вопрос | Решение |
|---|---|
| Аудитория | Универсально, как Moodle. Специфику школ, вузов и компаний добавляют модули |
| Стек | TypeScript, Next.js 16 (App Router) + PostgreSQL 18, монорепо pnpm + Turborepo |
| Установка | Одна организация на установку, без мультитенантности |
| Лицензия | AGPL-3.0 |
| Дизайн | Чистый и спокойный (Notion / Google Classroom). Бренд-цвет и логотип настраиваются. Тёмная тема, mobile-first, WCAG 2.1 AA |
| Языки | Русский по умолчанию + английский, next-intl с первого дня |
| AI | Подключаемые провайдеры: Claude по умолчанию + OpenAI-совместимый API (Ollama, vLLM, YandexGPT) |
| Объём v1 | Ядро + коммуникации + видео/вебинары + стандарты/импорт + AI-помощник |
| Язык кода | Код, комментарии и `docs/architecture.md` на английском. README на ru + en |

## Стек и версии

- **Платформа.** Node 24, pnpm 10, Turborepo 2, Biome 2 (линтер и форматтер с a11y-правилами).
- **TypeScript закреплён на 5.9**: TS 7 (нативный) пока рискован для тулинга Next. Можно добавить отдельный CI-job на TS 7, не блокирующий сборку.
- **Next.js 16.4, React 19.3.** `output: 'standalone'`, `proxy.ts` вместо middleware, `cacheComponents` выключен.
- **Данные.**
  - Prisma 7.10 с `prisma-client` generator, `@prisma/adapter-pg` и мультифайловой схемой.
  - Postgres-расширения: pgvector, citext, pg_trgm, unaccent.
  - Ключи UUIDv7.
- **Ядро.** zod 4 — единые схемы для форм, actions, REST, настроек модулей и AI-вывода. Better Auth 1.x — аутентификация. pg-boss — очереди без Redis.
- **UI.** Tailwind 4 и Radix-компоненты в стиле shadcn в собственном `packages/ui`. Также lucide, next-themes, sonner, TanStack Table/Virtual, dnd-kit, react-hook-form.
- **Контент.**
  - Tiptap 3 (только MIT-расширения): JSON — источник истины, плюс санитизированный HTML. Формулы через KaTeX.
  - Хранилище S3-совместимое (MinIO в compose), для разработки — драйвер файловой системы.
- **Почта и тесты.** nodemailer + React Email, в разработке письма ловит Mailpit. Тесты: vitest 5, Testcontainers, Playwright + axe.

## Архитектура

```
hubium/
  hubium.config.ts          # реестр модулей-плагинов (web + worker)
  apps/web               # Next.js: UI (RSC), server actions, REST /api/v1, SSE, файловые роуты
  apps/worker            # pg-boss: письма, перекодирование видео, импорт, AI, cron
  packages/db            # Prisma-схема, миграции, клиент, сиды, raw SQL (pgvector, tsvector)
  packages/core          # вся бизнес-логика без next/react: права, курсы, оценки, файлы, уведомления, AI-фичи
  packages/module-sdk    # контракт ActivityModule и ModuleCtx (модули не импортируют core)
  packages/ui            # дизайн-система: токены OKLCH, тема, оболочка, примитивы
  packages/editor        # Tiptap: клиентский редактор + серверная валидация/рендер/извлечение текста
  packages/i18n          # сообщения ru/en; worker тоже использует их для писем
  packages/questions     # типы вопросов, движок оценивания, импорт GIFT / Moodle XML
  packages/ai            # адаптеры LLM (Anthropic, OpenAI-compat) и эмбеддингов
  packages/interchange   # свой бэкап/восстановление, импорт .mbz
  modules/content        # page, file/folder, url/embed, label
  modules/{assign,quiz,forum,video,livesession,scorm,lti}
  docker/                # compose (dev: только инфраструктура; prod: всё + Caddy), Dockerfile
```

**Ключевые принципы**

1. **Одна операция — три транспорта.**
   - `defineOperation({ input, output, authorize, handler })` в `packages/core/src/operation.ts`.
   - Одна и та же операция работает как server action (`toAction`), как REST-роут (`toRoute`, Hono + OpenAPI) и вызывается из worker.
   - Авторизация всегда внутри операции. Побочные эффекты транзакционны: задачи pg-boss ставятся в той же транзакции, `pg_notify` срабатывает после коммита.
2. **Все типы активностей — модули.** Даже встроенные: страница, задание, тест и т.д. Контракт `ActivityModule` (`packages/module-sdk/src/activity-module.ts`) включает:
   - схему настроек (zod), UI редактора и просмотра;
   - хуки оценивания, правила выполнения, события календаря, «к выполнению» на дашборде;
   - actions, роуты, задачи;
   - бэкап и импорт из Moodle, извлечение текста для AI, приватность (экспорт/удаление данных).

   Сторонний плагин = пакет + строка в `hubium.config.ts` + пересборка. Модуль включается и выключается в админке.
3. **Права как в Moodle, но проще.**
   - Контексты: система → категория → курс → активность. У сущности и её контекста общий id.
   - Роли и их права хранятся в БД, переопределения работают на любом уровне. Значение PROHIBIT перекрывает всё.
   - Права объявлены в коде и типизированы, опечатка не скомпилируется.
   - Роли из коробки: manager, coursecreator, editingteacher, teacher (ассистент), student, observer, guest.
   - Админ сайта — флаг на пользователе. Он не появляется в списках студентов.
   - На странице `/admin/permissions/check` видно, почему у пользователя есть или нет права.
4. **Файлы.**
   - Адресация как в Moodle: `context/component/area/itemId/path`, неизменяемые blob-ы, дедупликация при копировании курсов.
   - Загрузка идёт в черновую область и прикрепляется при сохранении формы.
   - Скачивание только через ACL-роут с коротким подписанным URL. Бакет никогда не публичный.
5. **Realtime.** SSE + Postgres LISTEN/NOTIFY: без отдельного сервиса и без Redis. Одно соединение на браузер (выбор лидера через BroadcastChannel).
6. **Аутентификация** через Better Auth:
   - вход по email или логину (для школьников без почты);
   - OAuth: Google, Яндекс ID, VK ID;
   - 2FA (TOTP);
   - пароли импортированных из Moodle пользователей (bcrypt) принимаются и пересохраняются;
   - согласие на обработку ПДн (152-ФЗ).
7. **Недоверенный контент** (SCORM, сырой HTML) отдаётся с отдельного origin (`CONTENT_HOST`), куда не попадает сессионная cookie.

## Модель данных

Подробные поля — в файле разбора.

- **identity:** User, Session, Account, Verification, TwoFactor, UserRelation (родитель/наставник), ApiToken, Policy/PolicyAcceptance
- **site:** SiteSetting, EventLog, BackgroundTask, Tag
- **access:** Context (`ancestorIds uuid[]` + GIN), Role, RoleCapability, RoleOverride, RoleAssignment, RoleAssignRule
- **course:** Category, Course, CourseSection (дробный rank), Activity (`moduleKey`, settings Json, availability Json, completion), CourseAccess
- **enrol:** EnrolmentMethod (manual/self/cohort/guest, ключ, сроки), Enrolment, Group, GroupMember, Grouping, Cohort
- **completion / calendar:** ActivityCompletion, CourseCompletion, CalendarEvent, CalendarFeedToken
- **files:** FileBlob, File, FileVariant, UploadSession
- **grades:** GradeCategory (агрегации), GradeItem, Grade, GradeHistory, Scale, GradeLetter
- **comms:** Announcement, Conversation, ConversationMember, Message, Notification, NotificationPreference
- **questions:** QuestionCategory, Question (типы: multichoice, truefalse, shortanswer, numerical, match, essay, description)
- **Модули:**
  - **assign:** Submission, Grade, Override
  - **quiz:** Slot, Attempt, QuestionAttempt (снимок вопроса), Step, Override
  - **forum:** Discussion, Post, Subscription, ReadState
  - **video:** Asset, Caption, Progress
  - **livesession:** Session, Attendance, Recording
  - **scorm:** Package, Sco, Attempt, Track
  - **lti:** Tool, Deployment, PlatformKey, LaunchState, LineItem, AccessToken
- **ai:** AiProvider (ключ зашифрован), AiFeatureConfig, AiCourseFeature, AiConsent, AiUsage, ContentChunk (`vector(1024)`, HNSW), AiGeneration, GradingSuggestion, TutorConversation/Message

## Этапы

Каждый этап заканчивается рабочей версией `v0.N`, которую можно запустить и прокликать. Можно остановиться или поменять приоритеты между этапами.

**Статус (октябрь 2026).** Все восемь этапов реализованы и покрыты тестами (unit/интеграционные на PostgreSQL и сценарии Playwright с проверкой axe). Не сделано или проверено только частично:

- вебхуки REST API, опциональный ClamAV, структурные логи pino и OpenTelemetry;
- извлечение текста из PDF/DOCX для AI (тьютор и генерация используют текст страниц, описаний и меток);
- сценарии k6 написаны и проверены на одном пользователе, но не прогонялись под нагрузкой на эталонной машине;
- LTI, BigBlueButton/Jitsi и встраивания проверены на фейковых серверах и модульных тестах, без живого инструмента saLTIre/ltijs; импорт `.mbz` — на синтетических архивах, а не на корпусе реальных бэкапов Moodle 4.1/4.5/5.x;
- живой smoke-тест Claude API запускается только при наличии ключа (ночная сборка);
- ручная проверка с NVDA/VoiceOver не проводилась; Docker-образы в этой среде не собирались.

### Этап 1 — Фундамент

- **Монорепо и инфраструктура.**
  - Монорепо с Turbo, Biome и dependency-cruiser (правила: core без next/react, модули без core).
  - LICENSE (AGPL-3.0), README ru/en, CONTRIBUTING.
  - GitHub Actions: lint, typecheck, unit, integration, build.
  - docker compose: db (`pgvector/pgvector:pg18`), minio, mailpit, migrate, web, worker.
- **db:** базовые схемы `identity`, `site`, `access`, `files`. Сид: админ и демо-пользователи.
- **core:**
  - env (zod), шифрование секретов (AES-GCM), AppError;
  - фреймворк операций;
  - права: `can()`, кэш с NOTIFY-инвалидацией, синхронизация capabilities;
  - настройки, драйверы хранилища (S3/FS), ACL-роут файлов, EventLog;
  - сервис пользователей (CRUD, блокировка, CSV-загрузка), почта.
- **ui:**
  - токены и тема;
  - генератор палитры из бренд-цвета с автоисправлением контраста;
  - оболочка: сайдбар, топбар, нижняя навигация на мобильных, skip-link;
  - базовые компоненты.
- **web:**
  - вход, регистрация, подтверждение почты, сброс пароля, 2FA, OAuth-кнопки;
  - профиль и настройки: язык, часовой пояс, сессии;
  - админка: пользователи, редактор ролей (матрица прав), проверка прав, общие настройки, брендинг, регистрация, почта.
- **worker:** запуск, `email.send`, health.
- **Приёмка:**
  - после `docker compose up` админ входит в систему;
  - письмо подтверждения приходит в Mailpit, 2FA работает;
  - смена цвета и логотипа применяется;
  - переключение ru/en и тёмной темы сохраняется;
  - ≥40 unit-сценариев `can()` проходят.

### Этап 2 — Ядро обучения

- **Модули и редактор.**
  - module-sdk v1 и `modules/content` как эталонные модули: страница, файл/папка, ссылка/встраивание, метка.
  - Редактор Tiptap: формулы, таблицы, картинки, встраивание YouTube / RuTube / VK Video.
- **Структура курса.**
  - Дерево категорий.
  - Курсы: форматы «темы», «недели», «одна страница»; обложка.
  - Секции и активности в режиме редактирования: drag-and-drop + доступное с клавиатуры «Переместить в…».
  - Видимость, корзина.
- **Доступ.**
  - Условия доступа: дата, выполнение, группа, профиль.
  - «Посмотреть как студент», вход под пользователем.
- **Записи на курс.** Ручная, самозапись (с ключом и групповыми ключами), глобальные группы, гостевой доступ, сроки записи.
- **Участники и группы.** Участники с фильтрами и массовыми действиями, группы, группировки.
- **Прогресс.** Выполнение активностей и курса, процент прогресса.
- **Навигация.**
  - Дашборд: мои курсы с прогрессом, «продолжить», дедлайны, «к выполнению».
  - Каталог с поиском (tsvector + pg_trgm), лендинг курса.
  - Календарь (месяц, неделя, повестка) и iCal-фид.
- **Отчёты:** участие, матрица выполнения.
- **Приёмка (e2e):**
  - преподаватель собирает курс и включает запись по ключу;
  - студент записывается, попадает в группу, проходит всё и получает 100% прогресса;
  - событие появляется в календаре.

### Этап 3 — Оценивание

- **Журнал оценок.**
  - Категории, агрегации, веса, отбрасывание худших, шкалы, буквенные оценки.
  - Таблица оценщика с инлайн-редактированием и историей.
  - Отчёт студента, экспорт CSV/XLSX, импорт CSV.
  - Агрегацию проверяю фикстурами против расчётов Moodle.
- **mod-assign.**
  - Текстовый ответ и файлы.
  - Даты: открытие, срок, жёсткий срок. Продления, повторные попытки.
  - Панель проверки «работа + оценка рядом» с отзывом и файлами.
  - Скачивание всех работ zip-архивом.
- **Банк вопросов.** Шесть типов + описание, предпросмотр, теги. Попытка хранит снимок вопроса.
- **mod-quiz.**
  - Страницы и случайные вопросы из категории, перемешивание.
  - Лимит времени на сервере: задача закрытия + sweeper.
  - Автосохранение, методы оценивания, настройки просмотра результатов.
  - Ручная проверка эссе, статистика вопросов, переоценка.
- **Приёмка (e2e):**
  - тест с лимитом времени закрывается сам при закрытом браузере;
  - эссе проверено вручную, итог курса пересчитан;
  - задание сдано после продления и оценено с файлом отзыва.

### Этап 4 — Коммуникации

- **Уведомления.**
  - SSE-хаб.
  - Центр уведомлений и колокольчик со счётчиком.
  - Настройки по типам и каналам. Почта сразу или дайджестом, отписка в один клик.
- **Сообщения.** Личные и групповые, чаты групп курса, «печатает…», вложения, блокировки, приватность.
- **mod-forum.**
  - Типы: обычный и «вопрос-ответ».
  - Групповые режимы, подписки, непрочитанное, закрепление и блокировка тем, приватные ответы, модерация.
  - Выполнение по постам.
- **Объявления.** Лента курса как в Classroom и объявления сайта, отложенная публикация.
- **Подключение событий:** уведомления от заданий, тестов, записей на курс, календаря и форума.
- **Приёмка:** сообщение между двумя браузерами доходит быстрее 1 с; после переподключения ничего не теряется; дайджест приходит.

### Этап 5 — Видео и вебинары

- **mod-video.**
  - Возобновляемая загрузка (S3 multipart через Uppy).
  - ffprobe, затем ffmpeg → HLS 360/720/1080 (не выше исходника) в отдельном контейнере `worker-media` с лимитами CPU.
  - Постер, превью для перемотки, субтитры VTT/SRT.
- **Плеер.** hls.js + media-chrome. Адаптеры YouTube / RuTube / VK Video.
- **Прогресс просмотра.** Учёт просмотренных интервалов, запрет перемотки вперёд (опция), выполнение при N% просмотра.
- **mod-livesession.**
  - Интерфейс `LiveProvider` с реализациями BigBlueButton (API с checksum, коллбэки, записи) и Jitsi (JWT для своего сервера или meet.jit.si).
  - Расписание в календаре, роли модератор/участник по правам, посещаемость, записи.
- **Приёмка:** 1080p-ролик перекодируется и проигрывается; выполнение при 90% просмотра; BBB: создать → войти преподавателем и студентом → посещаемость → запись (нужен тестовый BBB-сервер).

### Этап 6 — Стандарты и импорт

- **mod-scorm (SCORM 1.2/2004).**
  - Безопасная распаковка: защита от zip-slip и zip-bomb.
  - Разбор `imsmanifest.xml`.
  - Отдача с `CONTENT_HOST`, рантайм scorm-again.
  - CMI, попытки, оценка, отчёт, отладка CMI.
- **mod-lti (LTI 1.3, сторона платформы, на `jose`).**
  - Ключи с ротацией и JWKS.
  - OIDC-запуск, Deep Linking, AGS (оценки идут в журнал), NRPS.
- **interchange.**
  - Свой формат `.hubium`: бэкап, восстановление, дублирование курса.
  - Импорт `.mbz` (Moodle 4.1 / 4.5 / 5.x).
  - Импорт вопросов GIFT и Moodle XML.
- **Приёмка:**
  - SCORM-пакеты Rustici Golf, iSpring и Storyline сохраняют статус, балл и продолжение;
  - LTI e2e против тестового инструмента на ltijs;
  - `.mbz`-фикстуры импортируются с отчётом;
  - бэкап → восстановление даёт тот же курс.

### Этап 7 — AI-помощник

- **Провайдеры.**
  - `LlmProvider`: `generateObject`, `generateText`, `streamText`.
  - Anthropic через `@anthropic-ai/sdk`: модели в настройках, по умолчанию `claude-sonnet-5-5` / `claude-haiku-5-5`; structured output, prompt caching, учёт токенов. Перед реализацией загружаю skill `claude-api` и сверяю API.
  - OpenAI-совместимый адаптер.
  - Эмбеддинги отдельным провайдером, по умолчанию bge-m3 через Ollama (compose-профиль `ai-local`).
- **Администрирование.** Включение по фичам и курсам, квоты, журнал использования, версия уведомления о приватности и согласие. Без провайдера все AI-элементы скрыты.
- **Генерация вопросов** по выбранным материалам. Результат — черновики в банке вопросов, преподаватель принимает или правит их.
- **Ассистент проверки.**
  - Работа анонимизируется.
  - Результат: оценка по критериям и черновик отзыва.
  - Кнопка «Применить» только заполняет форму, сохраняет сам преподаватель.
- **Тьютор для студента.**
  - RAG: pgvector + полнотекстовый поиск, слияние через RRF.
  - Ищет только по доступным студенту материалам, вопросы тестов исключены.
  - Отключается на время попытки теста.
  - Ответы со ссылками на источники.
- **Приёмка:** CI на мок-провайдере с записанными ответами; тест, что скрытые материалы не попадают в выдачу; квоты работают; каждый вызов пишет AiUsage.

### Этап 8 — Укрепление и API → v1.0

- **REST API v1.** Hono + OpenAPI 3.1, документация Scalar на `/api/v1/docs`, персональные токены со scope, вебхуки.
- **PWA.** Установка на устройство, Web Push.
- **Безопасность.** CSP на каждый запрос, проверка Origin, защита от SSRF, лимиты загрузок, опционально ClamAV, osv-scanner, CodeQL.
- **Приватность.** Экспорт и анонимизация данных пользователя через хуки модулей.
- **Доступность.** axe во всех e2e, ручная проверка с экранным диктором.
- **Нагрузка и эксплуатация.** k6 (1000 одновременных попыток теста), структурные логи, `/api/health`, руководство по бэкапу и обновлению.

**Вне v1 (бэклог v2):** SSO (SAML/OIDC/LDAP), сертификаты и бейджи, геймификация, H5P, «Семинар» (workshop), совместное редактирование, вычисляемые оценки, мобильное приложение (API к нему готов), xAPI/LRS.

## Как веду работу

- Коммит в конце каждого этапа и тег `v0.N`. Сообщения коммитов описывают только суть изменений.
- **Порог каждого этапа:**
  - `turbo lint typecheck test build` зелёный;
  - чистый `docker compose up` здоров;
  - сид с демо-данными этапа;
  - Playwright e2e ключевых сценариев;
  - ручной прогон во встроенном браузере: ru/en, светлая/тёмная тема, ширина 375px.
- После каждого этапа — короткий отчёт: что можно открыть и прокликать, что не проверено.
- В начале этапа 1 — четыре быстрых спайка, снимающих главные риски совместимости:
  1. Better Auth + Prisma 7;
  2. Next 16 + workspace-пакеты + standalone;
  3. pg-boss в транзакции Prisma;
  4. next-intl без префикса в URL.
- **Внешнее, что понадобится позже:**
  - OAuth-ключи Google / Яндекс / VK (опционально);
  - тестовый BigBlueButton (этап 5);
  - ключ Claude API или OpenAI-совместимый endpoint (этап 7).

  Без них соответствующие функции собираются и тестируются на моках, а живую проверку отмечу как непройденную.

## Главные риски

1. **Объём v1 очень большой.** Этапы независимы, модули включаются и выключаются, этапы 5–7 можно переставлять, v2-фичи не трогаем.
2. **Свежесть Next 16 / Prisma 7 / React 19.3.** Бизнес-логика в core без фреймворка, TS закреплён на 5.9, спайки в первый же день. Если Prisma-адаптер Better Auth не дружит с новым генератором — запасной вариант через Kysely-адаптер.
3. **Причуды SCORM.** Отдельный origin, нестрогий режим лимитов, keepalive-коммиты, набор реальных пакетов в тестах.
4. **Разнообразие `.mbz`.** Терпимый парсер, отчёт импорта, заглушки для неизвестных активностей. Код Moodle не копируем, реализуем по формату.
5. **Безопасность LTI.** Только RS256, одноразовые state/nonce, точное совпадение `redirect_uri`, SSRF-защита при загрузке JWKS.
6. **AI и данные в РФ.** Claude API доступен не во всех регионах, есть 152-ФЗ. Поэтому провайдер явно выбирает администратор, OpenAI-совместимый адаптер полноценный, данные для проверки анонимизируются, нужно согласие пользователя.
7. **Лицензии зависимостей.** Allowlist совместимых с AGPL лицензий в CI, только MIT-расширения Tiptap. Образ MinIO закреплён, но подходит любое S3-хранилище: Yandex Object Storage, VK Cloud, Selectel, Garage.

## Проверка (end-to-end)

1. `pnpm i && docker compose -f docker/compose.dev.yml up -d && pnpm db:migrate && pnpm db:seed --profile demo && pnpm dev` → `http://localhost:3000`.
2. `pnpm turbo lint typecheck test build` — зелёный.
3. `pnpm e2e` (Playwright на собранном приложении + worker + Mailpit) — сценарии текущего этапа зелёные, axe без serious/critical.
4. `docker compose -f docker/compose.yml up --build` — продовый стек поднимается, админ входит.
5. Ручной обход во встроенном браузере: админ → создание курса → студент проходит курс. Начиная с этапа 3 — тест и задание, с этапа 4 — сообщения в двух вкладках, и так далее по этапам.
