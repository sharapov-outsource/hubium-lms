# Languages

Hubium LMS ships its interface in Russian, English, French, German and Italian. A language is a set of message files: adding one needs no code. Administrators choose the site language and which languages users may pick in **Administration → Languages**.

The French, German and Italian packs were machine-translated with the terminology of Moodle's official translations. A review by native speakers is welcome: the files are plain JSON.

## Where the strings live

| File | Holds |
|---|---|
| `packages/i18n/messages/<code>.json` | the interface, with the `$language` block that describes the language |
| `modules/<module>/messages/<code>.json` | a module's strings (the `mod` namespace, e.g. `mod.quiz.start`) |

A language exists when its core file exists. Module files are optional: a module without the file shows its strings through the fallback chain below. The code is a language tag such as `de` or `pt-BR`.

`scripts/i18n-index.mjs` turns the files into a static index (`packages/i18n/src/generated/`), so Next.js, the worker bundle and the tests all load the same packs and nothing reads message files from disk at run time. It runs on `pnpm install`, and `pnpm i18n:index` runs it by hand. A test fails when the index is out of date.

## The `$language` block

```json
{
  "$language": {
    "name": "Deutsch",
    "englishName": "German",
    "tag": "de-DE",
    "dir": "ltr",
    "fts": "german",
    "letters": [["A", 90], ["B", 80], ["C", 70], ["D", 60], ["F", 0]]
  },
  "common": { "save": "Speichern" }
}
```

| Field | Use | When left out |
|---|---|---|
| `name` | the language in itself, in pickers | the name Intl knows |
| `englishName` | the language named to the AI (e.g. "write the questions in German") | from Intl |
| `tag` | BCP-47 tag for dates and numbers, `lang` of emails | the code |
| `dir` | `ltr` or `rtl` for `<html dir>` | the script's direction from Intl |
| `fts` | PostgreSQL text search configuration (`SELECT cfgname FROM pg_ts_config`) for catalog and AI search | `simple`: words are found, but without stemming |
| `letters` | default letter grades, as `[letter, lowest percent]` | the English letters A–F |

Only `ru` has letters of its own (5, 4, 3, 2). Sites and courses can set their own letters in the gradebook.

## Fallback

A user sees a string in their language. When the pack lacks it, the string comes from the site language, then from English (the base pack, which is complete by test). A string is never shown empty or broken.

Every string of every pack is checked against English when the pack is loaded, with the same ICU parser next-intl uses. A string is dropped, and the fallback shown instead, when it:

- is empty;
- does not parse (unbalanced braces, a tag that is not a tag);
- has other placeholders than English (`{name}` renamed or lost);
- has a plural without the `other` form.

**Administration → Languages** shows each pack's completeness. Missing, dropped and unknown keys are listed with their reasons.

## Which language a page uses

1. The course's forced language, on that course's pages (course settings → Language).
2. The language in the user's profile.
3. The language a guest chose (cookie).
4. The browser's languages, when **Detect the language of guests** is on.
5. The site language.
6. English.

Only enabled languages count. A user whose language was disabled or removed sees the site language. Emails and notifications go out in the user's language when it is enabled, otherwise in the site language.

## Adding a language

1. Copy `packages/i18n/messages/en.json` to `<code>.json` and translate the values. Fill in the `$language` block.
2. Optionally copy each `modules/*/messages/en.json` to `<code>.json` and translate it.
3. Run `pnpm i18n:index`, then `pnpm --filter @hubium/i18n test`. The test lists every missing or broken string.
4. Build and deploy. The language appears in **Administration → Languages**, enabled.
5. When the migrate step runs the seed, the language's `fts` configuration is added to the search and existing courses are re-indexed.

### Rules for translators

- Keep the keys and their nesting. Translate the values only.
- Keep placeholders as they are: `{name}`, `{count}`. Keep plural blocks: `{n, plural, one {# file} other {# files}}`. A plural may be added where English has a plain `{n}`, and `other` is required.
- Write apostrophes as `’`. In ICU an ASCII `'` before `{`, `}` or `#` quotes them, and the placeholder disappears.
- Keep tags such as `<docs>…</docs>`. Do not write anything else in angle brackets: `‹short name›` is fine, `<short name>` is not.

### Adding a string

A new interface string goes into every pack shipped in the repository (`ru`, `en`, `fr`, `de`, `it`). The test requires each of them to be complete. A pack outside the repository may lag behind: the fallback covers it.

## Texts that administrators enter in several languages

Role names, custom profile field names and policies are stored as `{ "<code>": "text" }`. Their forms have a field for every enabled language, and the site language's field is required. When the user's language has no text, the site language's text is shown, then English, then any.

Built-in roles take their names from the packs (`admin.role.archetypes.*`). A language added later gets its role names on the next seed; names set by an administrator are kept.
