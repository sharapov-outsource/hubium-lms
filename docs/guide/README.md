# Руководство пользователя Hubium LMS

Это руководство объясняет, как пользоваться Hubium LMS:
- **учащимся** — как учиться;
- **преподавателям** — как вести курсы;
- **менеджерам** — как строить отчёты;
- **администраторам** — как настраивать сайт.

Установка, обновление и обслуживание сервера описаны отдельно, в [руководстве по эксплуатации](../operations.md).

## Роли

Что пользователь может делать, определяют его роли. Роль выдаётся в одном из трёх контекстов и действует там и ниже:
- для всего сайта (системная роль);
- для категории курсов;
- для отдельного курса.

| Роль | Кратко |
|---|---|
| Администратор | Управляет всем сайтом, ему доступно всё. Это отдельный флаг учётной записи, а не обычная роль. |
| Менеджер | Ведёт пользователей, категории, курсы, глобальные группы и отчёты. Настройки сайта и состав прав в ролях меняет только администратор. |
| Создатель курсов | Создаёт новые курсы и становится в них преподавателем. |
| Преподаватель | Полностью ведёт свой курс: содержание, участники, группы, оценки. |
| Ассистент | Помогает вести курс: проверяет работы и выставляет оценки, но не меняет содержание курса. |
| Студент | Проходит курс: открывает материалы, сдаёт работы, получает оценки. |
| Наблюдатель | Наставник или родитель: видит успехи связанных с ним учащихся. |
| Гость | Может смотреть курс с гостевым доступом, ничего не сдавая. |
| Пользователь | Любой вошедший человек: профиль, сообщения, календарь, каталог. |

Администратор может менять права ролей и создавать свои роли. Подробнее — в разделах [Роли и права](06-admin.md#роли-и-права) и [Роли и права в курсе](04-teaching.md#роли-и-права-в-курсе).

## Основные понятия

**Курсы и их содержание**
- **Курс** — место, где идёт обучение. В курсе есть разделы, участники, журнал оценок и настройки. Курсы лежат в **категориях**, а категории могут быть вложенными.
- **Раздел** — часть курса: тема, неделя или модуль программы. Внутри раздела могут быть **подразделы**.
- **Элемент курса** — то, с чем работают учащиеся: страница, файл, задание, тест, форум, книга, вебинар и другие. Все виды элементов описаны в главе [Элементы курса](03-activities.md).
- **Банк вопросов** — хранилище вопросов курса, из которого собираются тесты.

**Участники и группы**
- **Способ записи** — как люди попадают в курс: их записывают вручную, они записываются сами (по кодовому слову или без него), курс синхронизируется с глобальной группой или открыт гостевой доступ.
- **Глобальная группа** — список пользователей на уровне сайта, например «Набор 2026». Её можно связать с курсами, и тогда все её участники будут записаны.
- **Группа** — часть участников внутри курса. **Группировка** — набор групп.
- **Режим групп**: без групп, видимые группы (участники видят работу других групп) или раздельные группы (каждый видит только свою).

**Права**
- **Роль** — набор прав.
- **Право** — разрешение на конкретное действие, например «оценивать задания».

**Прохождение и оценки**
- **Выполнение** — отметка о том, что учащийся закончил элемент: вручную или автоматически по условиям. Из выполнения элементов складывается **прогресс** и выполнение курса.
- **Условия доступа** — правила, когда открывается элемент или раздел: с даты, после выполнения другого элемента, при определённой оценке, для группы и т. д.
- **Журнал оценок** — все оценки курса: элементы, категории, итоги, формулы.
- **Шкала** — словесные оценки вместо баллов, например «не зачтено / зачтено».

**Достижения**
- **Значок** — цифровая награда за выполнение условий, в формате Open Badges.
- **Сертификат** — PDF-документ с уникальным кодом, который можно проверить на сайте.
- **Компетенция** — умение или знание из **фреймворка компетенций**.
- **План обучения** — набор компетенций, которые учащемуся предстоит освоить.
- **Свидетельство** — подтверждение освоения компетенции, которое добавляет сам учащийся.

**Обслуживание**
- **Режим обслуживания** — время, когда сайтом пользуются только администраторы, например при обновлении.
- **Локальный узел** — сервер Hubium в сети филиала или корпуса. Люди этой сети работают через него и продолжают работать, когда пропадает связь с основным сервером.
- **Конфликт** — работа, сделанная на узле без связи, которую основной сервер не принял. Её может принять преподаватель курса или администратор.
